Risks:

- The classification gate names `record_audit_entry`, but `Queen.stepLoop()` does not call it for in-cap payments.
- `require_human_approval` records an escalation note and returns pending; it is safe, but not a complete human approval workflow.
- The sibling `payment-intelligence-system` repo was not audited in this run.

### SIS Memory + Cockpit Lane

Evidence:

- `/api/audit` reads registry CSV data, checks local repo presence, and runs `git branch --show-current` plus `git status --short`.
- `/api/recover` is simulated and returns status/timestamp only.
- `/swarm` is static/config rendering of the swarm tree.
- Root cockpit mutates only local React state/log UI while calling audit/recover APIs.

Risks:

- `git status` can refresh Git index metadata, so `/api/audit` is operationally read-only but not guaranteed zero-write at `.git` metadata level.
- No authentication is visible; the cockpit must remain local-only unless auth is added.
- If exposed, `/api/audit` can leak repo inventory, roles/scopes, active branches, dirty counts, and possibly local path context in errors.
- Recovery UI can overstate reality because backend recovery is simulated.
