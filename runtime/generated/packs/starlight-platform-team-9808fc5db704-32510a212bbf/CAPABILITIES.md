# Skills, MCP, and integrations

## Team bindings

- Skills: `starlight-work-ledger`, `starlight-agent-ledger`, `starlight-swarm-orchestration`, `repo-harness`
- Plugins: `starlight-control-plane`
- Tools: `git`, `python`, `powershell`, `github`, `vercel`

Bindings describe requested capabilities. The runtime adapter must resolve each one against a deny-by-default allowlist and current credential scope.

## Integration choices

- **MCP** standardizes governed tools and resources; it is not a scheduler or permission system.
- **Composio** can reduce connector implementation work only after tenant isolation, action-level authorization, data processing, audit, and revocation are verified.
- **n8n** handles deterministic event and SaaS automation; it does not own durable missions.
- **OpenHands** is a bounded repository engineering specialist, not another control plane.
- **OpenClaw** is not admitted as a parallel personal gateway; absorb useful specialist patterns behind the Hand/worker contract.
- **Mastra or LangGraph** belong inside a specific activity only when state-graph behavior or TypeScript-native orchestration earns their complexity.
- **Dify** is optional for a validated low-code product team, not substrate for Starlight authority.
